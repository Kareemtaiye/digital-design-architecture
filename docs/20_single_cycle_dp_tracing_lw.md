# Single-Cycle Datapath: Tracing `lw`

## Build method: state elements first, then wire connections one at a time

Following the previous design process from: start with the four state elements (PC, instruction memory, register file, data memory), then add combinational logic between them piece by piece, one instruction type at a time. `lw` is the first instruction traced through, since it exercises every major piece of the datapath: register read, immediate handling, ALU, memory access, and register writeback.

## The full `lw` path, traced with real values

Example: PC = `0x1000`, fetched instruction = `0xFFC4A303` (`lw x6, -4(x9)`).

**1. Fetch.** PC connects directly to the instruction memory's address input. Instruction memory reads out the 32-bit `Instr` at that address, whihc is purely combinational, no clock involved (same as every memory/regfile read learned back in ch5/ch6).

**2. Read base register.** `lw` is I-type, so the base register is `rs1` = `Instr[19:15]`. Those bits connect straight into the register file's `A1` port. Register file returns `RD1` — in the example, `x9` holds `0x2004`. This is literally the same regfile port (`A1`/`RD1`) built back in `ch5-sequential-building-blocks/regfile.sv`, now wired into a bigger system instead of tested in isolation.

**3. Sign-extend the immediate.** The 12-bit immediate lives at `Instr[31:20]`. It's signed, so a dedicated **Extend unit** copies the sign bit (`Instr[31]`) into all upper bits: `ImmExt[31:12] = Instr[31]`, `ImmExt[11:0] = Instr[31:20]`. Example: `0xFFC` (12-bit two's complement −4) becomes `0xFFFFFFFC` (32-bit −4). This is a new, small combinational module — not something built in earlier chapters, but conceptually identical to every two's-complement sign-extension already worked through by hand for `lw`/`addi` immediates back in ch6.

**4. Compute the effective address.** An ALU takes `SrcA` = the base address (`RD1` from the regfile) and `SrcB` = the sign-extended offset (`ImmExt`), and adds them. `ALUControl = 000` selects addition (reusing the ALU built in `ch5-digital-building-block/base_alu.sv`). Example: `0x2004 + 0xFFFFFFFC = 0x2000`.

**5. Access data memory.** `ALUResult` (`0x2000`) feeds the data memory's address port `A`. Since `lw` reads, the memory returns `ReadData` at that address — `10` in the example. Same combinational-read/clocked-write RAM behavior from ch5.

**6. Write back to the register file.** `lw`'s destination register is `rd` = `Instr[11:7]`, connected to the register file's write port address `A3`. `ReadData` connects to `WD3`. A new control signal, **RegWrite**, drives `WE3` and is asserted for `lw` so the write actually happens. The write occurs on the rising clock edge at the _end_ of the cycle. Everything upstream (fetch, register read, sign-extend, ALU, memory read) happened combinationally within the same cycle; only this final write is clocked.

## PCNext — computed in parallel

While `lw` executes, a separate adder computes `PCNext = PC + 4` (instructions are always 4 bytes). This value is loaded into the PC register on the next rising clock edge. Example: `0x1000 + 4 = 0x1004`. This confirms the fetch-loop model from the stored program concept is literally just this adder plus the PC register, now made concrete as real hardware instead of a conceptual "PC increments by 4" description.

## What's genuinely new vs. what's reused

| Piece                                           | Status                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------- |
| PC register                                     | New (ch7-specific state element)                                                |
| Instruction memory                              | New, but same read behavior as ch5 RAM                                          |
| Register file (`A1`, `RD1`, `A3`/`WD3`/`WE3`)   | **Reused directly** from ch5                                                    |
| Sign-extend / Extend unit                       | New module                                                                      |
| ALU (`SrcA`, `SrcB`, `ALUControl`, `ALUResult`) | **Reused directly** from ch5                                                    |
| Data memory                                     | New, but same read/write behavior as ch5 RAM                                    |
| RegWrite control signal                         | New — first real control signal, generated by what will become the control unit |
| PC+4 adder                                      | New (small, dedicated adder)                                                    |

The datapath isn't new hardware from scratch. It's the ch5 register file and ALU, plus a handful of new glue modules (PC, sign-extend, PC+4 adder), wired together with one new control signal (`RegWrite`) driving the write enable that was already sitting on the regfile's write port.
