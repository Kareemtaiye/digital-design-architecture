# Computer Architecture Notes: The Volatile Memory Landscape

## The Core Engineering Tradeoff: Speed vs. Area vs. Cost

When designing hardware blocks or researching systems, memory choices are entirely governed by architectural constraints rather than raw physics. The overarching rule of thumb is: **Larger memory arrays are inherently slower due to physical routing delays and longer wire traces.**

---

## 1. Volatile Memory Comparison

| Memory Type            | Transistors per Bit | Latency / Speed          | Relative Density | Primary Architectural Use Case                    |
| :--------------------- | :-----------------: | :----------------------- | :--------------- | :------------------------------------------------ |
| **Flip-Flop**          |        ~20+         | Instant (0 clock cycles) | Extremely Low    | CPU Registers (`x0` to `x31`), Pipeline Registers |
| **SRAM** (Static RAM)  |          6          | Fast (~1–10 cycles)      | Medium           | Inside the CPU Core: L1, L2, L3 Cache lines       |
| **DRAM** (Dynamic RAM) |  1 (+ 1 Capacitor)  | Slow (~100+ cycles)      | Extremely High   | Main System Memory (Desktop RAM sticks)           |

### Key Architectural Takeaways:

- **Flip-Flops (`always_ff`)** provide instantaneous data availability at their output pins, but their massive transistor footprint makes them too expensive and space-consuming for deep storage.
- **SRAM** cuts transistor count using a cross-coupled latch circuit, but requires driving an address bus and bitline, introducing minor latency.
- **DRAM** achieves extreme density by using a lone transistor and an analog capacitor "bucket" to trap charge.
  - It suffers from high latency because charge moves slowly from the capacitor down an un-driven bitline.
  - It is destructive on reads and leaky over time, requiring periodic **refresh cycles** to prevent data loss.

---

## 2. Pipelining & Clock Exploitation (SDRAM / DDR)

When physical chemistry limited how fast a DRAM capacitor could discharge, systems engineering bypassed the roadblock using logical design:

- **SDRAM (Synchronous DRAM):** Introduced a global clock signal to memory modules. This allowed the CPU to **pipeline** memory requests, initiating a new bank access every clock cycle before the prior one finished.
- **DDR (Double Data Rate):** Optimizes bandwidth by transferring data on **both the rising and falling edges** of the clock cycle. This effectively doubles memory throughput without demanding a higher, power-hungry clock frequency.

---

## 3. Storage Misconceptions: ROM vs. Flash vs. Disk

Memory architectures hide physical implementations beneath strict logical classifications:

- **True ROM (Read-Only Memory):** Hardwired directly into the silicon layout at the factory. Used strictly for unchangeable bootloader code.
- **Flash Memory (SSDs):** Non-volatile storage that traps electrons in insulated floating-gate cages. Unlike ROM, applying high-voltage pulses allows blocks to be written and erased dynamically.
- **HDDs (Hard Disk Drives):** Mechanical magnetic media platters, entirely separate from solid-state silicon chip fabrics.

---

## 4. Hardware Realization: Logic Arrays & Memory Modeling

- **Memory as Logic:** Memory and combinational logic are mathematically interchangeable. An array can store a logic function's entire truth table (acting as a Look-Up Table, or **LUT**), which is the underlying secret behind how FPGAs emulate hardware circuits.
- **SystemVerilog Modeling:**
  - Writing an `always_ff` block with a clocked write condition alongside an unclocked continuous `assign` statement for reads creates a hybrid memory architecture.
  - In commercial ASIC environments, this code synthesizes into space-heavy flip-flop blocks unless replaced by optimized, black-box layouts generated by **Memory Compilers**.
